# EduWorld — Database

Schema: `supabase/migrations/0001_init.sql` · Seed: `supabase/seed.sql` (generated by `npm run seed:sql`) · Row types: `src/types/db.ts`.

## Keys
- **User data** uses `uuid` primary keys (`gen_random_uuid()`).
- **Content** (curricula, subjects, worlds, topics, lessons, questions, achievements, game_items) uses stable **text slugs** (`math.fractions`, `math.fractions.l1.c3`). Content is versioned in git and referenced from attempts/progress by slug, so re-seeding never breaks history.

## Tables

| Group | Table | Notes |
|---|---|---|
| Accounts | `users` | 1:1 with `auth.users`, created by trigger `on_auth_user_created`; `role` parent/admin |
| | `parent_profiles` | display name, `consent_at` (parental consent) |
| | `parent_settings` | `settings_json`: PIN hash, AI toggles, limits, schedule, allowed subjects, notifications |
| Children | `child_profiles` | nickname, `age_years` + `age_recorded_year` (no birth date), `age_group`, `current_grade` (independent of age), `custom_level`, `country_code`, `curriculum_id`, `interface_language`, preferences, `avatar_config`, `assessment_completed_at` |
| Content | `curricula` | `status` draft/reviewed/published/archived, `version`, `source`, `official` |
| | `subjects`, `worlds`, `topics` (`prerequisites text[]`), `grade_subjects` | |
| | `lessons` (`content jsonb`, `status`, generated `published`), `questions` (`question_data jsonb`) | |
| | `achievements`, `game_items` | |
| Learning | `lesson_attempts` | kind lesson/boss/assessment/review, score, rewards granted |
| | `question_attempts` | `is_correct`, `hint_used`, minimal `answer_data` (purged after 180 days) |
| | `learning_progress` | per child × topic: mastery, attempts, recent window, status, spaced-review stage, `next_review_at`; unique (child, topic) |
| Game | `game_profiles` | level, xp, total_xp, coins (≥0), streaks, `home_config` |
| | `child_achievements`, `inventory` (unique child × item), `daily_challenges`, `child_challenges`, `game_sessions` | |
| AI | `ai_sessions`, `ai_messages` (deleted after 90 days; stored only if parent allows) | |
| Parent control | `daily_activity` | minutes per child per day (limits & analytics) |

Indexes cover the hot paths: children by parent, attempts by child/time, question attempts by attempt, AI messages by child/time, daily challenges by date.

## RLS summary
- `parent_profiles`, `parent_settings`, `child_profiles`: only the owner (`auth.uid()`).
- All per-child tables: `public.is_my_child(child_id)` (security definer helper).
- Content tables: read-only for everyone; lessons/questions only when published/reviewed.
- `daily_challenges`: read for authenticated users; insert only for today's date.
- `delete_my_account()` lets a signed-in parent delete their auth user (cascades everything).

## Applying
```bash
supabase link --project-ref <ref>
supabase db push            # applies migrations
npm run seed:sql && psql "$DATABASE_URL" -f supabase/seed.sql
```
Schedule `select public.purge_old_answers();` daily (Supabase cron / pg_cron).
